# NEO Core — Maintainer Role Definition

Maintainers are the **operational stewards** of the NEO Core (L1) repository.  
They ensure that every change—technical, procedural, or symbolic—preserves the cathedral’s doctrinal integrity.

This document defines:

- what maintainers **are allowed** to do  
- what maintainers **are forbidden** to do  
- how maintainers exercise their authority  
- how maintainers coordinate with the Founder  
- how maintainers protect L1 architecture over decades  


---

# 1. Appointment & Authority

Maintainers are:

- appointed directly by the **Founder**  
- removable only by the **Founder**  
- bound by the **Founder-Key governance**  
- responsible for the long-term stability of the L1 codebase  

Maintainer status is a **stewardship role**, not ownership, leadership, or voting power.

**Maintainers do not have authority over doctrine, governance, or the NEO brand.**


---

# 2. Maintainer Responsibilities

Maintainers are required to:

### **2.1 Enforce Doctrine & Architecture**
- uphold Zero-Log, Zero-Storage, Zero-Surveillance  
- ensure Core never touches DOM  
- protect adapter boundaries  
- reject any PR violating doctrine  

### **2.2 Perform PR Review**
- check Stonecutter’s Note + Mason’s Oath  
- confirm CI status  
- check for doctrinal drift  
- validate pack integrity  
- confirm adapter stability invariants  

### **2.3 Maintain Technical Stability**
- apply emergency patches for adapter drift  
- update snapshots for nightly CI  
- maintain selector guards  
- ensure pack manifest alignment  
- verify SHA256 pack hashes  

### **2.4 Manage Contributor Interactions**
- uphold Code of Conduct  
- provide respectful, rigorous feedback  
- de-escalate tensions  
- suspend contributor access when needed  

### **2.5 Document System Health**
- contribute to stability logs  
- document recurring issues  
- update internal notes for future maintainers  

### **2.6 Stewardship During LOCKED STATE**
When Founder declares LOCKED STATE:

- maintainers freeze non-critical merges  
- address only Class 1 structural fixes with approval  
- keep CI running  
- communicate state to contributors  


---

# 3. Maintainer Powers (What Maintainers *Can* Do)

Maintainers may:

### ✔ Merge PRs  
Only when:

- all doctrine checks pass  
- all CI checks pass  
- pack hashes match  
- no structural change is involved  
- the Mason’s Oath is properly affirmed  

### ✔ Approve Standard Engineering Changes  
Including:

- performance improvements  
- documentation updates  
- adapter selector updates  
- pack manifest housekeeping  
- non-doctrinal logic refinements  

### ✔ Reject PRs  
For reasons including:

- doctrinal breaches  
- architecture violations  
- security concerns  
- lack of clarity or documentation  
- adversarial or sloppy code  

### ✔ Engage Contributors  
Maintain respectful, rigorous communication.

### ✔ Request Founder Review  
For any change approaching structural significance.

### ✔ Conduct Emergency Fixes  
Adapter drift, platform DOM changes, or broken masking may be addressed promptly—provided fixes remain within L1 boundaries and do not affect doctrine.


---

# 4. Limits of Maintainer Authority  
*(What Maintainers **Cannot** Do)*

Maintainers **may NOT**:

### ❌ Modify L0 Doctrine  
- Zero-Log  
- Zero-Storage  
- Zero-Surveillance  
- Non-Substitution Mandate  
- Child Protection Doctrine  
- Founder Sovereignty Charter  

### ❌ Modify Governance  
No edits to GOVERNANCE.md without Founder-Key.

### ❌ Modify Licensing  
The NEO Core L1 License may not be changed.

### ❌ Approve Structural (Class 1) Changes  
Any change affecting:

- architecture  
- adapter contracts  
- perception pipeline  
- pack loading system  
- veil logic  
- classification logic  
- doctrinal enforcement code  

requires **Founder-Key signature**.

### ❌ Sign Releases  
Only the Founder signs attestation.json and final build hashes.

### ❌ Appoint New Maintainers  
Only the Founder may nominate or remove.

### ❌ Introduce Telemetry, Analytics, or Storage  
Instant removal and LOCKED STATE if attempted.

### ❌ Publish or Represent NEO Externally  
Maintainership does not grant representational authority.

---

# 5. Maintainer Conduct Requirements

Maintainers must:

- operate with humility and precision  
- embody NEO’s safety-first philosophy  
- avoid ideological, emotional, or political entanglements  
- treat all contributors with respect  
- maintain clear communication  
- declare uncertainty when needed  
- ask for Founder review when in doubt  

Maintainer misconduct triggers immediate suspension pending review.


---

# 6. Suspension & Removal

The Founder may suspend a maintainer when:

- doctrine is violated  
- negligence endangers safety  
- code is merged without proper review  
- security weakness is introduced  
- contributor is harassed or mistreated  
- governance boundaries are crossed  

Suspension is unilateral and may occur without prior notice.

Removal requires no justification beyond Founder sovereignty.


---

# 7. Maintainer Onboarding

Before being granted maintainer status, candidates must:

- read all Umbrella documents (LICENSE, GOVERNANCE, SECURITY, CONTRIBUTING, CODE_OF_CONDUCT)  
- understand adapter contract and boundaries  
- pass a doctrinal comprehension check  
- perform one supervised merge  
- sign a Maintainer Stewardship Affirmation  

No maintainer gains authority without explicit Founder approval.

# 8. Amendments
